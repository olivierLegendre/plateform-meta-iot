# Authoritative Specifications

All documents in this folder are **authoritative** for the project.

## What belongs here

- Architecture baselines and migration plans
- System specifications and responsibilities
- PostgreSQL ownership and database operations contracts
- PoC parity baselines and mandatory equivalence rules
- Governance policies and operating model
- Normative roadmaps and target-state requirements

Execution tracking now lives in:

- `docs/project-monitoring/overview/`
- `docs/project-monitoring/services/`
- `docs/project-monitoring/waves/`

## Editing policy

1. Keep wording explicit and normative.
2. Avoid speculative language unless clearly labeled as assumption/hypothesis.
3. Update linked references when moving or renaming files.
4. Keep status/date/owner metadata up to date when present.

## Precedence

If a `docs/reports/*` statement conflicts with a `docs/specs/*` statement, the `docs/specs/*` statement is the source of truth.
